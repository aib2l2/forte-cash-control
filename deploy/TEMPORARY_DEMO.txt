ВРЕМЕННЫЙ ПУБЛИЧНЫЙ ПОКАЗ С ТЕКУЩЕГО MAC

Состояние:
  .venv/bin/python deploy/temporary_public.py status

Адрес, логин, пароль интерфейса и отдельный API-ключ:
  storage/public_demo/access.txt
Это закрытый файл с правами 0600 в каталоге 0700. Его нельзя включать в архивы,
скриншоты, Git и публичные отчёты. Пароль и ключ не выводятся командами status/start.

Проверка публичного пути с синтетическим видео:
  .venv/bin/python deploy/verify_temporary.py
Результат — storage/public_demo/verification.json. Это проверка транспорта,
очереди и интерфейса, а не качества модели на реальных операциях.

Остановка:
  .venv/bin/python deploy/temporary_public.py stop

Новый запуск после остановки:
  .venv/bin/python deploy/temporary_public.py start
Адрес и секреты изменятся. Скрипт не останавливает прежние процессы localhost
8000/8501 и не публикует локальный разметчик 8502.

Используются отдельные процессы: API 8010, UI 8510, Caddy 8765 — все слушают
только 127.0.0.1. HTTPS обеспечивает временный туннель Cloudflare. Интерфейс
защищён Basic Auth, API — отдельным X-API-Key. Исходные видео, разметка,
отчёт с описаниями и прежняя база задач не публикуются. Обработка загруженного
видео происходит в Python/R3D-18 на этом Mac, без внешнего AI API.

Необходимы текущая .venv и проверенные arm64-бинарники Caddy/cloudflared
в storage/public_demo/bin. Они загружены с официальных GitHub Releases;
SHA-256 сверены с метаданными релизов. Версии/хеши — bin/manifest.json.
На другом компьютере их нужно установить заново; бинарники и секреты не входят
в архив для постоянного контейнерного размещения.

Mac должен быть включён, иметь доступ в сеть и не спать. У временной ссылки
нет гарантии доступности. Для постоянного сервиса используйте подготовленный
deploy/compose.yaml на выделенном сервере с доменом. Постоянный сервер
и домен в этой сессии не были предоставлены.

Официальные инструкции:
https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/
https://caddyserver.com/docs/command-line
